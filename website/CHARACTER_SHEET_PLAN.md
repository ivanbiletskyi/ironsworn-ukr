# План: інтерактивний аркуш персонажа

Документ описує реалізацію інтерактивного аркуша персонажа для сайту `website/`
(українська фан-локалізація Ironsworn). Аркуш візуально повторює макет
паперового аркуша з набору «Залізна Присяга»
(`__zalizna-prysiaha-hralnyj-nabir__/…_page-0002.jpg`), зберігає стан локально
та вміє кидати граники.

**Статус:** реалізовано, етапи 1–9 закриті. Аркуш доступний за `/uk/character`.

---

## 1. Ухвалені рішення

| # | Питання | Рішення |
|---|---|---|

| 2 | Зберігання | `localStorage`, **кілька персонажів**, експорт/імпорт JSON |

| 5 | Імпульс | Апка **підказує, але не вирішує**: рахує вигоду від спалення й показує кнопку |
| 6 | Треки прогресу | Кнопка «Позначити» за рангом + ручні кліки по позначках + «Кидок прогресу» |

| 13 | Мова | **Тільки українська** |
| 14 | Показ кидка | Картка результату з граниками + легка CSS-анімація (без 3D-бібліотек) |
| 15 | Треки боїв/подорожей | **Окрема секція «Треки»** під аркушем, поверх 4 фіксованих присяг |

## 2. Термінологія

Аркуш використовує термінологію **сайту**, а не набору «Залізна Присяга», щоб
не суперечити текстам правил, на які веде навігація.

| Поняття | Термін сайту | У наборі (для довідки) |
|---|---|---|
| Dice | **граники** | кубики |
| Strong hit | **точне влучання** | точне влучання |
| Weak hit | **ледь влучаєте** | — |
| Miss | **промах** | промах |
| Rank 1 | **клопітний / клопітна** | КЛОПІТКА |
| Progress track | **шкала прогресу** | — |

Атрибути: **Вістря, Серце, Залізо, Тінь, Розум**.
Показники: **Здоров'я, Дух, Припаси**. Шкала: **Імпульс**.
Слабкості — стани (**Поранений, Розгубленість, Спантеличення, Перевантаження**),
тягарі (**Прокляття, Зморення**), згуба (**Скалічення, Спотворення**).

## 3. Правила, які кодуємо

Перевірено за `website/public/uk/`. Ці правила — джерело істини для логіки.

### 3.1 Хід дії

```
граник дії (d6) + атрибут + додатки  vs  два граники виклику (d10, d10)
```

* більше за **обидва** граники виклику → **точне влучання**
* більше за **один** → **ледь влучаєте**
* не більше за жоден → **промах**

Порівняння **строго більше**: рівність гранику виклику не є перемогою над ним.

### 3.2 Спалювання імпульсу
`1-Basics_4-Momentum.md`

При **позитивному** імпульсі після кидка гравець може скасувати **будь-які
граники виклику, значення яких менші за поточний імпульс** (строго менші).
Це не «заміна результату дії» — це видалення граників виклику.

Отже, апка рахує:

```
canceled = challengeDice.filter(d => d < momentum).length
```

і показує, який результат вийде після скасування. Кнопка «Спалити імпульс»
з'являється лише тоді, коли результат **покращується**.

Після спалення імпульс встановлюється на значення **скидання**.

### 3.3 Скидання імпульсу
`2-Your-Character_5-Debilities.md`

| Відмічених слабкостей | Скидання |
|---|---|
| 0 | **+2** |
| 1 | **+1** |
| 2 і більше | **0** |

> ⚠️ Це не «−1 за кожну слабкість». Правило порогове.

### 3.4 Максимальний імпульс

**Кожна** відмічена слабкість зменшує максимальний імпульс на 1 (базовий +10).
Тут правило справді лінійне — на відміну від скидання.

### 3.5 Негативний імпульс

Якщо імпульс < 0 і **дорівнює** значенню граника дії — граник дії скасовується.
Значення дії = атрибут + додатки, без d6.

### 3.6 Мінімальний імпульс

Імпульс не опускається нижче **−6**. Якщо гравець на мінімумі й хід каже
зменшити імпульс — замість цього робиться хід *Стріти невдачу*.
Апка показує підказку, але хід не автоматизує.

### 3.7 Позначки прогресу
`1-Basics_5-Progress-Tracks.md`

Шкала = 10 клітин × 4 позначки = 40 позначок.

| Ранг | За позначення |
|---|---|
| Клопітний | 3 клітини (12 позначок) |
| Небезпечний | 2 клітини (8) |
| Грізний | 1 клітина (4) |
| Екстремальний | 2 позначки |
| Епічний | 1 позначка |

Шкала стосунків рангу не має — завжди 1 позначка.

**Клік по клітині** працює як олівець на папері: порожня чи неповна клітина
отримує ще одну позначку, повна — стирається. Клік по клітині далеко попереду
переносить прогрес туди. Стирання клітини неминуче стирає й усі наступні —
прогрес зберігається одним числом, а не масивом клітин.

### 3.8 Кидок прогресу

Кидок прогресу порівнює **кількість повністю заповнених клітин** (не позначок)
із двома граниками виклику. Граник дії не кидається, імпульс не застосовується
й не спалюється.

### 3.9 Блокування показників

Якщо відмічено **Поранений** — не можна підвищувати здоров'я.
**Спантеличення** — дух. **Розгубленість** — припаси.
Кнопка «+» відповідного показника блокується з підказкою-поясненням.

## 4. Модель даних

Новий файл `src/utils/character/types.ts`.

```ts
export type AttrKey = 'edge' | 'heart' | 'iron' | 'shadow' | 'wits';
export type StatKey = 'health' | 'spirit' | 'supply';
export type Rank = 'troublesome' | 'dangerous' | 'formidable' | 'extreme' | 'epic';

export type DebilityKey =
  | 'wounded' | 'unprepared' | 'shaken' | 'encumbered'   // стани
  | 'maimed' | 'corrupted'                               // згуба
  | 'cursed' | 'tormented';                              // тягарі

/** 0 = порожній, 1 = зароблений, 2 = витрачений */
export type XpCell = 0 | 1 | 2;

export interface ProgressTrack {
  id: string;
  name: string;
  rank: Rank;
  /** 0–40 позначок; клітина = 4 позначки */
  ticks: number;
}

export interface ExtraTrack extends ProgressTrack {
  kind: 'combat' | 'journey' | 'other';
}

export interface Character {
  id: string;
  name: string;
  attributes: Record<AttrKey, number>;   // 0..4 (за створенням персонажа)
  stats: Record<StatKey, number>;        // 0..5
  momentum: number;                      // -6..max
  xp: XpCell[];                          // рівно 30
  vows: ProgressTrack[];                 // рівно 4 (як на аркуші)
  bondsTicks: number;                    // 0–40, шкала стосунків
  bondsNotes: string;
  debilities: Record<DebilityKey, boolean>;
  notes: string;                         // блок «ЗАПИСИ»
  extraTracks: ExtraTrack[];             // секція «Треки»
  updatedAt: number;
}

export interface CharacterStore {
  version: 1;
  activeId: string | null;
  characters: Character[];
}
```

`version` обов'язковий одразу — щоб майбутнє додавання профілів не зламало
збережених персонажів.

### Обчислювані значення (не зберігаються)

```ts
debilityCount = кількість true у debilities
maxMomentum   = 10 - debilityCount
resetMomentum = debilityCount === 0 ? 2 : debilityCount === 1 ? 1 : 0
```

Поля «МАКС.» і «ПОЧАТК.» на аркуші — **read-only**, із підписом-поясненням
(«−2 через 2 слабкості»).

### Ключі `localStorage`

| Ключ | Вміст |
|---|---|
| `ironsworn-characters-v1` | `CharacterStore` |
| `ironsworn-sheet-log-v1` | журнал кидків аркуша |
| `ironsworn-oracle-history-uk` | *існуючий, не чіпаємо* |

## 5. Движок кидків

Новий файл `src/utils/character/diceEngine.ts`. Не змінює `oracleEngine.ts`.

```ts
export type Outcome = 'strong' | 'weak' | 'miss';

interface BaseRoll {
  id: string;                    // ключ для React і видалення з журналу
  label: string;                 // «Вістря»
  challengeDice: [number, number];
  outcome: Outcome;
  matched: boolean;              // дубль на граниках виклику
  timestamp: number;
}

export interface ActionRollResult extends BaseRoll {
  kind: 'action';
  actionDie: number;             // 1–6
  stat: number;
  adds: number;
  actionScore: number;           // після скасування граника дії та обмеження в 10
  capped: boolean;               // сума перевищила 10
  actionDieCanceled: boolean;    // негативний імпульс
  canceledChallenge: [boolean, boolean];  // після спалення
  momentumBurned: boolean;
}

export interface ProgressRollResult extends BaseRoll {
  kind: 'progress';
  boxes: number;                 // 0–10
}

export type SheetRoll = ActionRollResult | ProgressRollResult;
```

Ключові функції, всі чисті й тестовані окремо від React:

```ts
rollAction(label, stat, adds, momentum): ActionRollResult
previewBurn(result, momentum): ActionRollResult | null   // null = не покращує
rollProgress(label, ticks): ProgressRollResult
```

`previewBurn` — саме та функція, що реалізує рішення №5: вона рахує наслідок,
а стан персонажа змінює лише обробник кнопки в UI.

Тип `SheetRoll` навмисно паралельний до `RollResult` з `oracleEngine.ts` —
щоб пізніше злити журнали в один без переписування компонентів.

```
  CharacterSheet.css

  useSheetLog.ts            # журнал кидків, свій ключ у localStorage
  CharacterBar.tsx          # перемикач персонажів, експорт/імпорт
  AttributeBoxes.tsx        # ВІСТРЯ +3 → клік кидає хід
  ScaleTrack.tsx            # спільна шкала значень
  MomentumTrack.tsx         # шкала +10..−6, МАКС., ПОЧАТК.
  StatTracks.tsx            # здоров'я / дух / припаси, 0..+5
  XpTrack.tsx               # 30 кружечків, три стани
  ProgressTrackRow.tsx      # 10 клітин × 4 позначки, ранг, кнопки
  DebilitiesBox.tsx         # чекбокси слабкостей
  ExtraTracksSection.tsx    # треки боїв/подорожей
  RollResultCard.tsx        # картка результату + анімація
  RollLog.tsx               # журнал кидків
src/utils/character/
  types.ts                  # типи, межі, константи правил
  rules.ts                  # обчислювані значення персонажа
  diceEngine.ts             # кидки
  storage.ts                # load/save/експорт/імпорт, міграції
  labels.ts                 # усі українські підписи в одному місці
```

`rules.ts` не було в початковому нарисі: обчислення макс./скидання імпульсу,
позначок і досвіду — це правила персонажа, а не типи й не кидки, тож тримати їх
окремо чистіше, ніж вантажити ними `types.ts`.

`ProgressTrackRow.tsx` навмисно один компонент для присяг, стосунків і треків
боїв — різниця лише в наявності рангу.

Окремих `BondsBox.tsx` і `NotesBox.tsx` із нарису не існує: стосунки — це той
самий `ProgressTrackRow` без рангу, а записи — звичайне текстове поле в зоні.
Заводити для них компоненти-обгортки не було чого.

## 7. Розкладка

Брейкпоінти взято з наявних у проєкті (`App.css` уже використовує 1200 / 900 / 480),
щоб не заводити третю систему порогів: **> 1200px** — паперова розкладка,
**≤ 1200px** — дві колонки, **≤ 700px** — одна колонка.
Поріг 1200, а не 1000, тому що на широкому екрані ліворуч ще стоїть сайдбар
на 300px — при вьюпорті 1200 аркушу лишається близько 900px.

### Десктоп (> 1200px) — як на папері

Реалізація — CSS Grid із іменованими зонами (`grid-template-areas`). **Усі** зони
живуть в одній сітці — включно з треками й журналом, які на ескізі вище стоять
окремим блоком. Інакше мобільний порядок (треки перед стосунками) був би
недосяжним без зміни розмітки: два окремі гріди неможливо перемішати між собою.

### Мобільний (≤ 700px) — вертикальна стрічка

Порядок секцій змінюється на ігровий, а не паперовий:

1. Ім'я + атрибути (5 великих кнопок-плиток, ≥ 56px)
2. **Останній кидок / картка результату**
3. Імпульс (горизонтальний, не вертикальний) + показники
4. Досвід
5. Присяги
6. Треки
7. Стосунки, слабкості
8. Записи
9. Журнал

Картка стоїть одразу за атрибутами, а не четвертою, як планувалося спершу:
панель кидка — це ряд під плитками характеристик, тож результат мусить
з'явитися там само. Інакше гравець тисне «Кинути» вгорі екрана, а картка
виникає через чотири екрани прокрутки.

Мінімальна ціль дотику — 44×44px. Треки прогресу на мобільному дають клік по
клітині (не по чверті); ручне тикання позначок доступне через довге натискання
або окрему кнопку «−».

## 8. Взаємодія: хід дії

1. Гравець тисне число на плитці атрибута → під плитками розгортається ряд
   із полем «додатки» (`+0` за замовчуванням) і кнопкою «Кинути». Саме ряд,
   а не спливаюче вікно над плиткою: попап над крайньою правою плиткою
   вилазив би за край екрана на телефоні.
2. `rollAction` повертає результат; `RollResultCard` показує граники з
   анімацією 300–400 мс.
3. Колір рамки картки: точне влучання — `--success`, ледь влучаєте —
   `--warning`, промах — `--danger`.
4. Якщо `matched` — підпис «ЗБІГ ГРАНИКІВ» (драматичний поворот).
5. Якщо `actionDieCanceled` — граник дії показано перекресленим із поясненням
   «негативний імпульс скасував граник дії».
6. Якщо `previewBurn` != null — кнопка `Спалити імпульс → ТОЧНЕ ВЛУЧАННЯ`.
   Натискання: оновлює картку, ставить `momentum = resetMomentum`, дописує в
   журнал окремий запис про спалення.
7. Запис іде в журнал.

Апка **ніколи** не змінює здоров'я, дух, припаси чи імпульс сама — окрім
скидання після явного натискання «Спалити імпульс» і одного винятку: коли
слабкість опускає максимум імпульсу нижче поточного значення, імпульс
підтягується до нового максимуму. Зворотного руху немає — знята слабкість
піднімає максимум, але не повертає втрачений імпульс.

### Оновлення стану — лише кроком, не готовим значенням

Кнопки, що змінюють значення відносно поточного (степери характеристик,
«Позначити»), передають **крок**, а нове значення рахується від актуального
стану всередині reducer'а. Інакше кілька натискань, що потрапили в один такт
React, прочитали б однакове застаріле значення: три кліки «+» дали б +1
замість +3.

## 9. Кілька персонажів, збереження, експорт

* Автозбереження з debounce 500 мс після будь-якої зміни.
* Перемикач персонажів у `CharacterBar` — випадний список + «Новий персонаж» +
  «Дублювати» + «Видалити» (з підтвердженням).
* Новий персонаж створюється з підказкою за створенням персонажа: атрибути
  порожні, показники +5, імпульс +2, макс. +10, скидання +2.
* **Експорт**: `Blob` → `zalizna-prysiaha-<ім'я>.json`, увесь `Character`.
* **Імпорт**: `<input type="file">`, валідація за `version`; невідома версія —
  явна помилка, не тихе падіння. Імпорт **додає** персонажа, не перезаписує
  активного.

`CharacterBar` — смуга **над** аркушем, а не частина зони «ПЕРСОНАЖ»: поле імені
лишається там, де воно на папері. Видалення підтверджується вбудованою кнопкою
«Точно видалити», а не `confirm()` — системне вікно не стилізується, блокує
сторінку й не піддається перевірці.

## 10. Інтеграція із сайтом

### Маршрут

У `src/App.tsx`, поряд із наявним рядком `oracles`:

```tsx
<Route path="character" element={<CharacterSheet />} />
```

### Тільки українська

Рішення №13 має наслідок, який треба обробити явно: сайт двомовний, і
`/en/character` буде доступний за замовчуванням. Тому:

* кнопку в навігації показуємо **лише** при `currentLang === 'uk'`;
* сам маршрут при `lang !== 'uk'` робить `<Navigate to="/uk/character" replace />`;
* `handleLanguageSwitch` у `Navigation.tsx` перемикає шлях підстановкою префікса
  — з `/uk/character` користувач потрапить на `/en/character` і буде негайно
  повернений назад. Це прийнятно, але кнопку «EN» на цій сторінці варто
  приховати або зробити неактивною, щоб не створювати мигання.

### Навігація

У `Navigation.tsx`, у блоці `nav-controls`, перед кнопкою оракулів:

```tsx
{currentLang === 'uk' && (
  <Link to="/uk/character" className="nav-icon-btn" title="Аркуш персонажа">📜</Link>
)}
```

Стиль `.nav-icon-btn` уже існує — нових CSS-класів для навігації не треба.

## 12. Тести

```
yarn test          # vitest: логіка правил + компонентні тести
yarn test:watch    # те саме у режимі спостереження
yarn audit:layout  # аудит розкладки у справжньому Chrome
```

Тексти тестів і коментарі — англійською; українською лишаються тільки ті
рядки, що є фактичними значеннями інтерфейсу.

### vitest (`yarn test`)

| Файл | Що покриває |
|---|---|
| `src/utils/character/__tests__/rules.test.ts` | правила з §3: імпульс, слабкості, позначки, досвід, межі |
| `src/utils/character/__tests__/diceEngine.test.ts` | хід дії, спалення імпульсу, негативний імпульс, кидок прогресу |
| `src/utils/character/__tests__/storage.test.ts` | нормалізація пошкоджених даних, експорт/імпорт, localStorage |
| `src/components/character/__tests__/sheet-basics.test.tsx` | автозбереження, редирект з не-української, слабкості → імпульс, блокування показників, характеристики |
| `src/components/character/__tests__/sheet-rolls.test.tsx` | кидок ходу дії, спалення, дубль, обмеження в 10, шкали прогресу, журнал |

Граники детерміновані через підміну `Math.random` (`stubDice` у
`__tests__/helpers.ts`). Збереження перевіряється розмонтуванням компонента:
`useCharacterStore` скидає незбережений стан у `localStorage` під час
розмонтування, тож фальшиві таймери не потрібні.

Тести навмисно виключені з `tsconfig.app.json`: продакшн-збірка не має
залежати від тестових пакетів.

### Аудит розкладки (`yarn audit:layout`)

Окремий скрипт, бо **jsdom не має рушія розкладки** — у ньому неможливо
виміряти ні горизонтальне переповнення, ні розміри цілей дотику. Скрипт
підіймає headless Chrome і працює через DevTools-протокол; потрібен запущений
`yarn dev`. Налаштовується через `SHEET_URL`, `CHROME_PATH`, `DEBUG_PORT`.

Що він гарантує:

* **320–1800px** — жодного горизонтального переповнення на 14 ширинах;
* **ціль дотику** — від 44px для шкал, степерів і кнопок треків, від 40px для
  кнопок панелі персонажів;
* **світла тема** — застосовується й не ламає розкладку;
* **`prefers-reduced-motion: reduce`** — вимикає анімацію граників.

## 13. Свідомо поза обсягом

* **Профілі (активи)** — окремий етап після релізу; `Character` уже має
  `version`, тож додавання поля `assets` не зламає збережених персонажів.
* **Англійська версія** аркуша.
* **Друк / експорт у PDF** — `@media print` не робимо.
* **Копіювання кидків у буфер** — попри те, що для оракулів це вже є.
* **Синхронізація між пристроями** — бекенду немає; заміна — експорт JSON.
* **Спільний журнал з оракулами** — тип підготовлено, злиття пізніше.
* **Автоматизація ходів** (Напасти, Вирушити в подорож тощо) — аркуш кидає
  граники за атрибутом, наслідки хода застосовує гравець.
