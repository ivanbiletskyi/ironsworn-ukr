# План: профілі на аркуші персонажа

Документ описує додавання **профілів** (у правилах сайту — «активи») до
інтерактивного аркуша персонажа `website/`. Профілі оцифровуються з набору
«Залізна Присяга» (`__zalizna-prysiaha-hralnyj-nabir__/profiles/`, 9 сторінок,
78 карток) і живуть на аркуші як **рука карт**: віяло невеликих карток унизу
аркуша на десктопі та приклеєний до низу екрана футер на телефоні.

Це рішення №8 з `CHARACTER_SHEET_PLAN.md` («Профілі (активи) — відкладено»),
яке тепер закривається. Усі домовленості того документа (термінологія §2,
розкладка §7, підхід до збереження §9, тести §12) лишаються чинними; тут
описано лише те, що додається.

**Статус:** план узгоджено; **етап 1 закрито** — усі 78 карток оцифровано
в `src/utils/profiles/` разом із тестами інваріантів. Далі етап 2.

## 2. Термінологія

`CHARACTER_SHEET_PLAN.md` §2 велить триматися слів сайту, а не набору. Для
профілів робимо виняток (рішення №21): гравець тримає перед собою паперові
картки з надписом «ШЛЯХ», і називати їх в апці «активами» — створювати
розбіжність там, де її найлегше помітити.

| Поняття | В апці | У правилах сайту (`public/uk`) |
|---|---|---|
| Asset | **профіль** | актив |
| Asset ability | **навичка** | здібність |
| Companion | **супутник** | супутник |
| Path | **шлях** | шлях |
| Combat talent | **бойовий талант** | бойовий талант |
| Ritual | **ритуал** | ритуал |

Порожній стан зони містить рядок «У правилах їх названо активами» з
посиланням на `/uk/2-Your-Character_6-Assets` — щоб зв'язок із главою не
загубився.

### Що на картці буває

Оцифрування має витримати всі ці випадки — вони й задають модель даних:

* **тип** у шапці (`СУПУТНИК` / `ШЛЯХ` / `БОЙОВИЙ ТАЛАНТ` / `РИТУАЛ`);
* **назва**;
* **порожні поля**: «Ім'я:» (супутники, «Тенета леза»), «Ім'я/назва:»
  («Вірний стягові»), «Ім'я божества:» + «Атрибут:» («Відданий»),
  «Титул/Родовід:» («Уповноважений»), «Ремесло:» («Ремісник»),
  «Досвід:» («Родич»);
* **вступний рядок** без кружечка («Ваш пес — це найвірніший союзник.»);
* **умова** з трьома точками («Щойно ви стали скаліченим…», «Якщо ви
  спорядили щита…») — той самий рядок, лише інша роль;
* **навички** з кружечком: закрашеним ● (надрукована як уже доступна) або
  порожнім ○;
* **вкладені списки**: з простими маркерами «•» («Вартове коло», «Лучник»,
  «Броненосець») і **з власними кружечками ○** («Маска»: вибір матеріалу);
* **жирний** («**Цей профіль вважається слабкістю**») і *курсив* назв ходів
  (*Здобуваєте перевагу*, *Стріти небезпеку*);
* **шкала** внизу картки — не завжди числова:
  * `0 +1 +2 +3 +4` — здоров'я супутника (довжина різна: до +2, +3, +4, +5);
  * `0 +1 +2 +3 +4` — сила ватаги («Командир»), статок («Мисливець за наживою»);
  * `0 … +6` — есенція («Виклик»), світло («Світлоносець»), здоров'я ляльки («Повстання»);
  * `ЛЕГКИЙ ОБЛАДУНОК | ВАЖКИЙ ОБЛАДУНОК` («Броненосець») — клітинки словами.

Тексту **не** розбираємо на механіку: жодних полів «атрибут», «додаток»,
«ранг», жодних посилань на ходи. Картка — це дерево тексту з відмітками.

## 4. Модель даних

### 4.1 Каталог (незмінний, у бандлі)

`src/utils/profiles/profile-types.ts`:

```ts
export type ProfileType = 'companion' | 'path' | 'talent' | 'ritual';

/** Порожня лінія на картці, у яку гравець вписує своє. */
export interface ProfileField {
  id: string;    // 'name' | 'deity' | 'attribute' | 'craft' | 'experience' | 'title'
  label: string; // «Ім'я:», «Атрибут:», «Ремесло:»
}

/**
 * Блок картки. Дерево, бо на картках є вкладені списки, і в частині з них
 * вкладені пункти мають власні кружечки («Маска»).
 *
 * Рівно одне з `text` і `field` заповнене. Поля — теж блоки, а не окремий
 * список картки: на «Родичі» лінія «Досвід:» надрукована між навичками, і
 * порядок блоків має відповідати паперу.
 */
export interface ProfileBlock {
  /** Кружечок ліворуч: як надруковано на папері. Без нього — просто абзац. */
  mark?: 'filled' | 'empty';
  /** Маркер «•» без кружечка: вкладений вибір, що не відкривається досвідом. */
  bullet?: boolean;
  /** Текст із розміткою **жирний** та *курсив*. Дослівно, як на картці. */
  text?: string;
  /** Замість тексту — порожня лінія для вписування. */
  field?: ProfileField;
  children?: ProfileBlock[];
}

/** Смуга клітинок унизу картки. Підписи — рядками: буває й «ВАЖКИЙ ОБЛАДУНОК». */
export interface ProfileTrack {
  cells: string[];
}

export interface Profile {
  /** Стабільний ключ `тип-транслітерація`: 'companion-yastrub', 'path-alkhimik'. */
  id: string;
  type: ProfileType;
  name: string;
  /** Вступний рядок і умова («Щойно ви стали скаліченим…») — блоки без відмітки. */
  blocks: ProfileBlock[];
  track?: ProfileTrack;
  /** Сторінка набору — щоб транскрипцію можна було звірити. */
  source: string; // 'page-0028'
}
```

Ключі транслітеровані, а не перекладені: англійські назви офіційних активів
довелося б угадувати, а хибний ключ лишився б у збереженнях гравців назавжди.

Файли: `profile-01-companions.ts`, `profile-02-paths.ts`,
`profile-03-talents.ts`, `profile-04-rituals.ts`, `index.ts` (зведений
масив `PROFILES` + `PROFILES_BY_TYPE` + `findProfile(id)`), — рівно так, як
влаштовані `src/utils/oracles/`. Повторюване виноситься в хелпери:
`healthTrack(max)` і `NAME_FIELD` у `profile-types.ts`, `RITUAL_BOOST`
(спільна третя навичка ритуалів) — у файлі ритуалів.

### 4.2 Стан персонажа (у `localStorage` і в хмарі)

`src/utils/character/types.ts`:

```ts
/** Профіль у руці персонажа: посилання на каталог + те, що вписав гравець. */
export interface CharacterProfile {
  /** Власний id рядка, як у присяг і треків. */
  id: string;
  /** Ключ каталогу. Невідомий ключ під час нормалізації відкидається. */
  profileId: string;
  /**
   * Шляхи відмічених кружечків у дереві блоків: '1' — другий блок верхнього
   * рівня, '0.2' — третій вкладений у першому. Позиція, а не назва: назви
   * навичок неунікальні, а порядок блоків у каталозі — незмінна частина даних.
   */
  marked: string[];
  /** Вписані значення полів картки, за `ProfileField.id`. */
  fields: Record<string, string>;
  /** Вибрана клітинка шкали; null — жодної. */
  trackIndex: number | null;
}

export interface Character {
  // …
  /** Рука профілів у порядку додавання. */
  profiles: CharacterProfile[];
}

export const STORE_VERSION = 4; // 3 → 4: у персонажа з'явилися профілі
```

Похідні значення (не зберігаються): `Profile` з каталогу за `profileId`,
кількість відмічених навичок для корінця карти, підпис карти
(`fields.name?.trim() || profile.name`).

### 4.3 Міграція та нормалізація

* **v3 → v4** окремої функції не потребує: `normalizeCharacter` добудовує
  `profiles: []`, коли поля немає. `STORE_VERSION` піднімається до 4, щоб
  файл експорту з профілями не читався старою версією аркуша молча.
* `normalizeProfile` відкидає запис, чий `profileId` немає в каталозі:
  каталог — джерело істини, а осиротілі відмітки нікуди показати.
* `marked` чиститься від шляхів, яких у дереві блоків немає, і від дублів.
* `trackIndex` обмежується довжиною `track.cells`; для карток без шкали — `null`.
* `fields` лишає лише ключі, оголошені в каталозі.
* `duplicateCharacter` перевидає `id` кожного профілю (як присягам і трекам).
* `isBlankCharacter` (`utils/sync/snapshot.ts`) додає умову
  `character.profiles.length === 0` — інакше персонаж із трьома профілями
  вважався б порожнім і синхронізація його зжувала б.

Формат документа Firestore не змінюється: знімок — це JSON персонажів
цілком, тож профілі синхронізуються без правок у `snapshot.ts` понад
`isBlankCharacter`.

## 5. Розкладка

### 5.1 Десктоп (> 1200px) і планшет (700–1200px)

Новий рядок сітки `profiles` — між «Слабкостями» і «Треками»:

```
'name     name     xp       xp'
'momentum attrs    attrs    stats'
'momentum vows     vows     stats'
'momentum notes    bonds    stats'
'momentum notes    debil    stats'
'profiles profiles profiles profiles'   ← нове
'tracks   tracks   tracks   tracks'
'log      log      log      log'
```

Для `@media (max-width: 1200px)` — так само один рядок `'profiles profiles'`
перед `'tracks tracks'`.

Зона — звичайна `Zone` із заголовком «ПРОФІЛІ» і кнопкою «+» праворуч
(проп `action`, як у присяг і стосунків).

```
┌─ ПРОФІЛІ · 5 ────────────────────────────────────────── + ─┐
│                                                            │
│              ╭──────────────╮                              │
│       ╭──────┤    ШЛЯХ      ├──────╮                       │
│  ╭────┤ СУПУТ│   Алхімік    │ РИТУАЛ├────╮                 │
│  │ШЛЯХ│ Пес  │   ● ○ ○      │ Шепіт │ШЛЯХ│                 │
│  │Тене│ ●●○  │              │ ●○○   │Кома│                 │
│  ╰────┴──────╰──────────────┴───────┴────╯                 │
│                    ↑ під курсором карта підіймається       │
└────────────────────────────────────────────────────────────┘
```

Клік по карті підіймає її на місці: карта виростає до читабельного розміру,
сусіди розступаються віялом ліворуч і праворуч, аркуш навколо лишається
видним.

```
┌─ ПРОФІЛІ · 5 ────────────────────────────────────────── + ─┐
│ ┌──────────────────────────┐   ╭────╮╭────╮╭────╮╭────╮    │
│ │ СУПУТНИК            ×    │   │ШЛЯХ││РИТУ││ШЛЯХ││ШЛЯХ│    │
│ │ Пес                      │   │Алхі││Шепі││Кома││Тене│    │
│ │ Ім'я: [Баск___________]  │   ╰────╯╰────╯╰────╯╰────╯    │
│ │ Ваш пес — це найвірніший │                               │
│ │ союзник.                 │                               │
│ │ ● Гострий нюх: Коли ви   │                               │
│ │   *Збираєте інформацію*… │                               │
│ │ ● Лютий: Коли ви…        │                               │
│ │ ○ Вірний: Коли ви…       │  ← затемнено, ще не відкрито   │

Ширина піднятої карти — `min(22rem, 100%)`; висота за вмістом. Найдовші
картки («Пов'язаний», «Вартове коло») лишаються цілими: зона росте, а не
обрізає текст.

### 5.2 Телефон (≤ 700px)

Зони `profiles` у сітці немає — замість неї приклеєний футер.

**Закритий** (завжди на екрані, ~44px + `env(safe-area-inset-bottom)`):

```
… аркуш …
────────────────────────────────
 ПРОФІЛІ · 4                  ▴
────────────────────────────────
```

`.character-sheet-page` отримує `padding-bottom`, що враховує висоту
футера, — інакше футер накриває журнал кидків.

**Розгорнутий** — шухляда з рукою карт, тло затемнене:

```
┌──────────────────────────────┐
│  ░░░ затемнений аркуш ░░░    │
├──────────────────────────────┤
│ ПРОФІЛІ · 4              + ▾ │
│   ╭────╮╭────╮╭────╮╭────╮   │
│   │ШЛЯХ││СУПУ││РИТУ││ШЛЯХ│   │
│   │Алхі││Пес ││Шепі││Кома│   │
│   │●○○ ││●●○ ││●○○ ││●○○ │   │
│   ╰────╯╰────╯╰────╯╰────╯   │
│        ← гортання вбік →     │
└──────────────────────────────┘
```

**Тап по карті** — картка на весь екран (рішення №6): читати текст на
телефоні у віялі неможливо.

```
┌──────────────────────────────┐
│ ‹ Профілі              ×     │
│  СУПУТНИК                    │
│  Пес                         │
│  Ім'я: [Баск______________]  │
│  Ваш пес — це найвірніший…   │
│  ● Гострий нюх: …            │
│  ● Лютий: …                  │
│  ○ Вірний: …                 │
│  │ 0 │ +1 │[+2]│ +3 │ +4 │   │
│                              │
│  ‹ 2 з 4 ›   [Видалити]      │
└──────────────────────────────┘
```

Закриття фулскріна повертає до розгорнутої шухляди, а не до аркуша:
гравець зазвичай дивиться другу карту одразу після першої. Гортання
«‹ 2 з 4 ›» і свайп вбік перегортають карти, не закриваючи екран.

### 5.3 Вікно вибору профілю (обидві платформи)

Повноекранне вікно, викликається «+»:

```
┌──────────────────────────────────────────────────────────┐
│  Додати профіль                                     ×    │
│  [ 🔍 пошук за назвою чи текстом навички______________ ] │
│                                                          │
│  СУПУТНИКИ · 10                                          │
│  ┌────────────┐┌────────────┐┌────────────┐┌───────────┐ │
│  │ Печерний   ││ Павук-велет││ Яструб     ││ Кінь      │ │
│  │ лев        ││            ││            ││           │ │
│  │ Ваш кіт    ││ Ваш павук  ││ Ваш яструб ││ Верхи на  │ │
│  │ хапає…     ││ розкриває… ││ може…      ││ коні…     │ │
│  └────────────┘└────────────┘└────────────┘└───────────┘ │
│                                                          │
│  ШЛЯХИ · 37                                              │
│  ┌────────────┐┌────────────┐┌────────────┐┌───────────┐ │
│  …                                                       │
└──────────────────────────────────────────────────────────┘
```

Плитка — тип, назва, вступний рядок або перші слова першої навички. Тап
розкриває повну картку поверх сітки з кнопкою «+ Додати» (рішення №12):

```
┌──────────────────────────────────────────────────────────┐
│  ‹ Назад                                            ×    │
│  ┌────────────────────────────────────────────────────┐  │
│  │ ШЛЯХ                                               │  │
│  │ Алхімік                                            │  │
│  │ ● Коли ви варите зілля, оберіть ефект: Спритність   │  │
│  │   (Вістря), Зухвальство (Серце)…                    │  │
│  │ ○ Ви можете зварити одну дозу з двома ефектами…     │  │
│  │ ○ Коли ви варите зілля, додайте +1 до кидка…        │  │
│  └────────────────────────────────────────────────────┘  │
│                                       [ + Додати ]       │
└──────────────────────────────────────────────────────────┘
```

Пошук фільтрує за назвою **і** за текстом навичок (шукати «щит», «припаси»,
«стосунки» — головний спосіб знайти потрібне серед 78). Групи, у яких після
фільтра нічого не лишилося, ховаються. Уже додані профілі у вікні не
показуються; лічильник групи показує кількість доступних.

### 5.4 Шари (z-index)

Наявний стос: шапка сайту 100, меню персонажів 50, картки-сповіщення 900,
мобільний сайдбар 1000/1001. Додаємо:

| Шар | z-index | Чому саме так |
|---|---|---|
| Приклеєний футер | 800 | Вище за аркуш, нижче за картку кидка: результат кидка важливіший |
| Шухляда з рукою + її тло | 850 | Над футером, під сповіщеннями |
| Фулскрін картки, вікно вибору | 950 | Над сповіщеннями (модальний екран перекриває все), під сайдбаром сайту |

## 6. Взаємодія

### 6.1 Додавання

1. «+» у заголовку зони (десктоп) або у смузі шухляди (телефон).
2. Вікно вибору → плитка → повна картка → «+ Додати».
3. Профіль стає останнім у руці й **одразу піднятим** — гравець бачить, що
   отримав, і може відмітити першу навичку супутника чи вписати ім'я.
4. Відмічені навички за замовчуванням — ті, що надруковані закрашеними
   (рішення №14). У супутників закрашених немає: карта додається з порожніми
   кружечками, і перший клік — вибір стартової навички.

### 6.2 Кружечки

* Клік перемикає (`role="switch"`, `aria-checked`). Помилковий клік
  скасовується повторним — жодних підтверджень і жодного списання досвіду.
* Відкрита навичка: `--text-primary`, кружечок залитий `--highlight`.
* Закрита: `--text-secondary`, кружечок — контур `--border-color`.
* Ціль дотику — **весь рядок навички**, не сам кружечок: так само зроблено
  зі слабкостями (`.debility { min-height: 44px }`).
* Вкладені кружечки («Маска») працюють точно так само — це той самий блок
  дерева, лише глибший шлях.

### 6.3 Поля й шкала

* Поле — `input` без рамки з підкресленням, як `.progress-track__name`;
  зберігається одразу (той самий debounce автозбереження, 500 мс).
* Значення поля `name` показується на корінці карти замість назви профілю
  («Баск», а не «Пес»), а назва профілю йде другим рядком.
* Шкала — `role="radiogroup"` з клітинками `.scale-cell`, як в імпульсу й
  показників; повторний клік по вибраній клітинці знімає вибір
  (`trackIndex: null`) — інакше «0» і «нічого не вибрано» не розрізнити.
* Числових правил шкала не має: жодних обмежень слабкостями, жодних кидків.

### 6.4 Видалення

* «×» у шапці **піднятої** карти (на телефоні — «Видалити» у фулскріні).
* Питаємо підтвердження, якщо в картці є робота гравця: відмічено щось
  понад надруковані ●, заповнене поле або вибрана клітинка шкали. Інакше
  прибираємо молча — це щойно доданий профіль.
* Повторно використовуємо `useTrackRemoval`-підхід: вбудований рядок
  підтвердження, а не `window.confirm` (він не стилізується).
* Підпис питання: «Видалити «Пес» разом із відмітками?»

  ProfileHand.tsx           віяло: розкладка, підняття, гортання, клавіатура
  ProfileCard.tsx           картка: шапка, поля, блоки, шкала (варіанти
                            spine / raised / full)
  ProfileMarks.tsx          рядок навички з кружечком (рекурсивно по дереву)
  ProfileTrackRow.tsx       смуга клітинок картки
  ProfilePicker.tsx         повноекранне вікно вибору: пошук, групи, прев'ю
  useIsNarrow.ts            matchMedia('(max-width: 700px)')
  CharacterSheet.tsx        + addProfile / updateProfile / removeProfile
  CharacterSheet.css        + зона, віяло, футер, шухляда, вікно вибору
```

`useIsNarrow` потрібен, бо мобільний потік — це три різні стани (смужка,
шухляда, фулскрін), яких CSS сам не змоделює, а дублювати руку в DOM двічі
означало б дублювати й `aria`, і те, що бачать тести. У jsdom `matchMedia`
віддає `matches: false`, тож тести за замовчуванням ганяють десктопну зону,
а мобільні випадки підміняють `matchMedia` явно.

`richText.tsx` навмисно свій, а не `MarkdownRenderer`: той тягне
`@uiw/react-markdown-preview` і повний markdown, тоді як картці треба два
правила — `*курсив*` і `**жирний**`.

## 8. Доступність

* Кружечок — `button role="switch"` із `aria-checked` і `aria-label`
  «Гострий нюх: відкрито / не відкрито».
* Рука — `role="list"`; корінець карти — `button` з `aria-expanded`;
  `←`/`→` перемикають карту, `Enter`/`Space` підіймає, `Esc` опускає.
* Футер — `button aria-expanded` + `aria-controls` шухляди.
* Фулскрін і вікно вибору — `role="dialog" aria-modal="true"`, фокус
  замикається всередині, `Esc` закриває, після закриття фокус повертається
  на кнопку, що відкривала.
* Ціль дотику ≥ 44px для всього інтерактивного на ≤700px (перевіряє
  `yarn audit:layout`).
* `@media (prefers-reduced-motion: reduce)` знімає підняття карти, виїзд
  шухляди й появу фулскріна — блок уже є в `CharacterSheet.css`.

## 11. Свідомо поза обсягом

* **Кидки з картки.** Текст не парситься, кнопок кидка немає (рішення №19).
* **Автоматика досвіду.** Ні ліміту профілів, ні списання 2 досвіду,
  ні перевірок вимог («Пошрамований» вимагає скалічення) — апка не
  вирішує за гравця (рішення №16).
* **Перетягування карт** у руці (рішення №22).
* **Дві копії одного профілю** (рішення №23).
* **Профілі з розширень** (Delve, Ironsworn: Starforged) — каталог рівно
  той, що в теці набору.
* **Друк карток**, експорт руки окремо від персонажа.
* **Англійська версія.** Аркуш існує лише українською
  (`CHARACTER_SHEET_PLAN.md` §10).
